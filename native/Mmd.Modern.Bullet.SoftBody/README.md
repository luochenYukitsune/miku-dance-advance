# Independent PMX soft-body bridge

Uses original Bullet 2.75 SoftBody files from the same SHA-locked distribution as the existing rigid library. `UPSTREAM.json` records all 18 unchanged files and the archive SHA. Bullet uses its retained zlib license. PMX parameter mapping references the MIT nanoem component; its license is retained separately.

Build the two product libraries from the product root with explicit output paths:

```powershell
python scripts/build-bullet-soft.py --output ../.dev-cache/bullet-cluster-bounds-20261114/soft/mmd_bullet_soft.dll
python scripts/build-bullet.py --output ../.dev-cache/bullet-cluster-bounds-20261114/rigid/mmd_bullet.dll
```

Output and compiler/cache/temp files stay under those workspace cache directories. The independent float32 `mmd_bullet_soft.dll` retains ABI1 and its own world; the coupled library includes the same prepared soft-body sources. Previous builds remain in their original cache directories. Product build defaults and packaging verification select the paths above; historical build-script default output paths are retained for existing callers.

Modern Clang requires a cache-only compatibility copy of `btSoftBodyInternals.h` to value-initialize its old template `zerodummy`. The source tree bytes stay unchanged; exact before/after hashes are recorded in the build manifest. A legacy narrowing diagnostic is disabled for old upstream helper initializers. Upstream warnings remain; a zero-warning claim would be incorrect.

Cluster input bounds: single-source and shared-source bodies reject a possible cluster extent above 46,340, including Bullet's optional master cluster, before allocating its signed-int square connectivity table. A separate cache-only `btSoftBody.cpp` patch widens the seed product `i * 29873` before modulo; node index 71,888 otherwise overflows even with only five clusters. Both build manifests record the original/generated hashes and the exact changed expression. The original third-party files stay unchanged. Focused native and managed checks cover rejection, reuse after failure, large single/shared sources and a small safe baseline's byte-identical samples; see [the boundary review](../../docs/stages/2026-11-14-soft-cluster-bounds.md).

The project dispatches soft/static-plane contacts directly through Bullet's soft/rigid contact algorithm. The original concave route extrudes generated plane triangles into convex hulls, giving the floor a position-dependent thickness; the native falling-cloth probe exposed node heights 0.068..0.121 instead of a uniform .02 margin. Direct dispatch also needs an analytic plane SDF: `btSparseSDF::DistanceToShape` originally returns zero for all non-convex shapes. The cache patch evaluates `dot(normal, localPoint) - planeConstant`; the existing SDF interpolation and solver remain in use. This semantic fix is separate from compiler compatibility, is recorded with source/compiled hashes, and is not claimed to reproduce original MMD output. The same native cloth settles uniformly at 0.020679 after the fix. Before/after trajectories are retained under the current stage's softbody evidence.

Implemented: material-local triangle/rope node topology, global-to-local pins and anchors, Bullet solver parameters, collision groups/masks, static ground, externally driven rigid collision/anchor proxies, target-pose world reset, positions and normals. Reset recreates contacts, velocities and SDF state at the supplied skinned pose; it does not save solver history.

Kinematic Near: original PMX bone-follow rigid mode is required. The ordinary anchor remains; after each actual physics step the selected node velocity receives rigid origin minus node position, without timestep scaling. This is an additional operation, not Bullet's collision-disable boolean. The PMXEditor0236 [specification backup](https://gist.github.com/FlandreDaisuki/90ae5abf3138a15994526b6bfec73c2c) documents the behavior; its full text is not vendored or labeled MIT. Saba and nanoem preserve the field but do not implement this extra operation. Reset reconstructs the pair list; Sample does not advance it. Existing pin target updates clear velocity before every subsequent step.

The ABI1 `mmd_soft_add` pair layout is unchanged. Additive `mmd_soft_features` bit0 advertises Kinematic Near, and `mmd_soft_near_anchors` validates a whole replacement list against existing ordinary anchor pairs before publication. Old ABI1 DLLs continue to work for ordinary inputs; Near reports explicit missing capability before candidate allocation. No vendored upstream files were changed.

Additional ABI1 capabilities: bit1 (`2`) supports cluster/analytic-plane contacts through the pair-specific adapter in `mmd_soft_plane_collision.h`. Plane pairs temporarily use upstream SDF node contacts, while cluster topology, CL_SS, and ordinary convex CL_RS contacts remain active. Native probes verify flag restoration, masks, disabled objects and a true Bullet static-plane shape; this is not original MMD numeric certification.

Bit2 (`4`) adds `mmd_soft_add_shared` and the read-only topology observer. Overlap-connected source materials use one body with unique original-vertex nodes, summed mass contributions, union pins, per-source materials and source-local bending. Singleton topology retains the old ABI path. Conflicting body-wide settings remain explicit unsupported combinations; no separate simulations or last-writer averaging is used.

Bit3 (`8`) adds atomic `mmd_soft_collider_poses`. It validates the complete transform batch before changing any proxy, preserving soft nodes, velocities and history. Malformed batch probes verify subsequent trajectories remain identical to the unchanged world. Older libraries reject missing capabilities before changing an active candidate.

Bit4 (`16`) supports overlapping cluster materials. Each source uses upstream Bullet cluster generation with its authored count; memberships and noncolliding masters are mapped to actual shared original-vertex nodes. Cluster mass/constants, pointer connectivity and trees are rebuilt after additive masses and union pins. Mixed cluster collision switches and incompatible body-wide settings reject explicitly. Old feature15 libraries reject this new combination before candidate publication, while ordinary singleton and shared noncluster inputs retain their old path.

Bit5 (`32`) enables the coupled binding's frozen collision surface. Additive `mmd_soft_attached_validate_frozen_surface` and `mmd_soft_attached_frozen_surface` share complete count, bound, face arithmetic and cluster-center validation. The first is read-only and works before freezing, allowing every scene actor to preflight before any publication. The second updates actual frozen node/face/cluster collision structures without changing saved solver history. Degenerate finite faces use zero normals; overflow rejects the whole batch. Face normals are saved and restored with node/cluster history so the first resumed aerodynamic step remains identical. Seek/reset is required to resume the controller at a deformed pose; this is not solver-history serialization.

The standalone library retains one-way proxy input. The explicitly selected coupled owner additionally compiles these soft sources into `mmd_bullet.dll`, borrowing actual rigid bodies in one numerical world without exposing Bullet pointers across DLL boundaries. Its provider supports ordinary contact/anchor reaction, Dynamic/DynamicAligned Near, suspended collider contacts, owner-only stepping and rigid-frame rebase. Source-authored Near ordering is retained. Standalone ABI1 remains available; the coupled ABI is additive.

Both build paths compile documented cache-only solver arithmetic matching the retained original contact expression tree. Generated units and copied headers are hashed before/after compilation; pristine third-party files stay unchanged. Project contact adapters handle coincident soft-contact normals and suspended contact-only participation.

Boundaries: conflicting body-wide configurations and mixed cluster collision switches reject explicitly. Original MMD9.32 rejects ordinary PMX2.1 headers before model data, so soft extensions cannot be labeled original-playback equivalence. Nonuniform frozen display/collision projection preserves the original trajectory rather than rebasing its velocity history. Current status and evidence are maintained in [CORE_COMPLETION](../../docs/CORE_COMPLETION.md).
