# 三语文案润色须知（给负责翻译的 AI）

目录：`src/Mmd.Modern.App/Assets/Localization/`。技术细节以同目录的 `README.md` 为准，本页只列润色时容易出错的地方。

## 现状（2026-11-17 检查）

- `zh-CN.json`、`en.json`、`ja.json` 各 1431 项，键完全一致。没有空值；`{0}` 这类占位符和换行数三语一致。
- 正式界面（`manifest.json` 里列出的 AXAML）没有漏掉的中文硬编码。
- C# 里还有 239 处中文字符串没进资源，大多在开发用的帧查看器、引擎演示和旧版 `MainWindow`（只能用 `--frame-viewer`、`--legacy-preview` 打开），普通用户看不到。`NativeLightControls`、`SceneObjectControls` 也在其中，属于同一套开发工具。这次润色不用管它们。
- 日文里约 140 项只有汉字，比如 位置、回転、設定，大多是正常的日文写法。真正需要看的是和中文完全相同的 19 项，例如 白、未指定，以及“受光方式”这种中文式说法。
- 另有 123 项中文候选稿，还在原开发机 `G:/MDA-Work/localization/20261114/zh-refresh/`，不在本仓库。要用就先拿过来，否则这次润色可以直接取代它。注意其中第 46／48／50 项讲的是“编码字节／解码容量／文件大小”，不是“像素尺寸”。

## 只能改值，不能动键

- 只修改三个 JSON 里的**值**。键不能新增、删除或改名。
- `manifest.json` 的 `literalToKey` 已冻结，不要改。哈希形式的键（`Mda.Text.xxxxxxxxxxxx`）来自最初的中文原文，改中文显示内容不影响 ID。
- 保持文件格式：UTF-8 无 BOM、CRLF 换行、键的原有顺序、合法 JSON、没有重复键。

## 必须原样保留的东西

- 占位符的个数和编号，包括 `{0:0.0}` 这类带格式的写法。可以按语序调整位置，但不能丢。
- 换行数，以及开头、结尾的空格：有些文本会被拼接，空格是故意留的。
- 菜单项结尾的 `…`。引号里提到的按钮名，必须和该按钮实际的译文一致。
- 不翻译：模型、骨骼、表情、材质、文件名、画风预设 ID，品牌名（MMD、MME、PMX、DLSS、FSR、XeSS……），扩展名，单位，轴名，`カメラ・照明`，版权文字，原作者署名（例如“舞力介入P”），字体版权行。
- 语言选项用各自的母语名称：简体中文、English、日本語。

## 措辞要求（沿用项目约定）

- 短标签保持简短。说明和报错写成自然平实的话，说清楚实际发生了什么、下一步该怎么做。
- 不编造控件、原因、自动行为，也不承诺性能或质量。
- 分清“应用修改”和“保存工程文件”；按字节计算的限制，不要写成像素。
- 英文、日文通常比中文长。要在最小窗口 680×460 下检查有没有被裁切，尤其是按钮、选项卡和检查器标签。

## 测试和并行冲突

- 34 个测试文件里，共有 84 行断言直接比较中文界面文字。改了中文措辞，这些测试会失败，需要同步更新期望，不能删掉断言。
- 改完至少跑一遍：
  - `python scripts/localize-editor-static.py --check`
  - `EditorRenderEngineSelectionTests` 里的资源检查（编码替换字符、目录一致性）
  - 相关的界面测试
- 并行风险：另外有几个分支正在往这三个 JSON 里**新增**键，包括 Classic 新 FX 分配页、Toon 十槽界面，以及之后的画风改造。
  - 润色请在单独的分支上做，合并时按键做三方合并，不要整文件覆盖。
  - 那些分支新增的键，等它们合并后再补一轮润色。
