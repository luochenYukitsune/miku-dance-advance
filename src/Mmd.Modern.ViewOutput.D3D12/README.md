# D3D12 view adapter

2026-10-24: [Endfield radial Hair](../../docs/stages/2026-10-24-endfield-hair.md) is verified. Optional `endfieldHairDataBindings` uses explicit ObjectId/local material/local Green texture, palette and signed brightness; same-sample source seed availability is required even for composed bindings. Optional scene-input preflight rejects active missing data before playback/export, while other local families remain dormant. This is not complete HA/HB, material-profile persistence or PMA schema.

2026-10-24 update: [Generic PMX processing](../../docs/stages/2026-10-24-pmx-general-treatment.md) now fills engine-owned family defaults only for explicitly mapped ordinary Body/Hair rows. Missing host rows remain untouched; explicit identity treatment opts out. Face/Eye/dedicated data and MMD remain protected. Schema11 persists model overrides, while style definitions stay in the renderer.

Historical first stage: [Explicit ordinary-PMX treatment](../../docs/stages/2026-10-24-pmx-material-treatment.md) is verified in Capture and Present. Pass `new D3D12ViewCharacterMaterialBinding(objectId, localMaterialIndex, new(Role: D3D12CharacterMaterialRole.Hair, PmxMaterialTreatment: new(Saturation: 1.02f, TransitionWidthScale: .9f)))` in the existing `characterMaterials` constructor argument. Only explicitly selected ordinary Body/Hair consumes it; Face/Eye/dedicated data coexistence rejects. Source objects, images and default MMD remain unchanged. Validation uses the final applied preset response. These are detached host settings, not PMA data or a change to engine preset defaults.

2026-10-23: [Temporal GI + SSAA combination](../../docs/stages/2026-10-23-temporal-ssaa.md) is verified. Each spatial sample owns independent preceding logical-frame history; one Submit publishes the complete set and abort preserves it. Unified driver-aligned memory preflight, soft/DXR reference comparisons and existing ViewOutput Capture/Present are verified. No core, MMD palette or reconstruction-AA rewrite. FSR/XeSS/DLSS temporal reconstruction + SSAA and transparent temporal output remain separate limitations.

`D3D12ViewRenderer` reuses `D3D12FrameSession.Capture`; `D3D12RealtimeViewRenderer` binds a backend-owned HWND and reuses `D3D12SwapchainPresenter`. The neutral module exposes neither Vortice types nor GPU resources. Capabilities report the actual hardware/WARP choice and the existing 4096-pixel dimension limit.

Project/PMA frames carry stable object IDs, explicit roles, effective preset references and actual material ranges. Both adapters accept an immutable `stylePresets` catalog; they apply it after the existing scene/camera/quality resolver. `D3D12ViewRenderingStyles` checks complete ranges and reports every unavailable effective reference, including hidden objects, before GPU work. The four ordinary-PMX style families are available only after explicit selection. Built-in `mmd` is the default and preserves incoming toon, outline and GI material parameters; custom MMD-pipeline presets remain explicit overrides. Character classification applies the established GI policy independently and does not itself enable modern toon or outlines. These preservation corrections are technically verified in the [four-style batch](../../docs/stages/2026-10-23-four-style-adaptation.md), which records exact validation scope and counts.

[D3D12ViewFaceSdfBindings](D3D12ViewFaceSdfBindings.cs) provides technically verified model-local face input transport for all four style families and their dedicated encodings. A binding identifies ObjectId, local Face material, source-local primary/secondary texture slots and either `FixedWorld` axes or a `SelectedBone` with local axes. The optional `faceDataBindings` constructor input is detached and exposes only selected neutral requests through `IViewSceneInputRequests`. Application captures those texture remaps and already solved head matrices with the geometry sample; PreviewFrame and OfflineFrame transport them on the existing clock. The adapter neither evaluates animation/physics nor guesses contiguous texture offsets or head names, and applies placement exactly once. Selected-bone mode requires an existing evaluated motion controller; fixed-world mode supports static objects. Images must already exist in the source SceneSnapshot texture table.

These inputs require an explicit matching Face declaration and compatible opt-in family; Eye/Body are not converted, and default MMD is never switched by a binding. Missing visible sample payload fails before GPU submission. Existing Face/Eye strengths and composed-frame bindings remain separate. Genshin Soft Shape consumes RGB plus mask G/A with cubic repeat sampling and adapts to the PMX palette; it does not implement the complete source soft/sharp palette. Binding GUI/PMA persistence, authored specialized assets and hair shaders remain outside this slice. The requested same-model/camera MMD-plus-four comparison uses honest ordinary-PMX fallback where compatible dedicated maps are absent.

`D3D12ViewRenderingStyleReplacements.Inspect/Prepare` exposes project-level missing references and available replacements without edits. A prepared plan's explicit `Confirm(project, token)` checks staleness and performs one existing metadata Undo transaction. The next ordinary PMA save remembers accepted references; confirmation itself never writes disk or embeds preset definitions. This adapter provides the backend contract; the formal replacement dialog remains GUI work.

Opaque captures preserve the established display bytes. This is the display/code-value rendering path, not a claim of physically linear lighting. Transparent capture uses the validated FP16 premultiplied intermediate and straight RGBA8 resolve. Unsupported transparent temporal-upscaling combinations remain explicit errors. No whole-frame gamma conversion is introduced.

Geometry/material morph evaluation comes from the core. The adapter consumes evaluated texture/sphere/toon factors and additional UV data carried by the combined scene, and resolved project/PMM cameras and shadow metadata through the existing resolver. Unsupported camera/shadow origins remain explicit errors. Existing scene AA settings are retained, and per-view GI defaults off; exact boundaries follow the current stage reports.

`ViewQualityOptions` independently overrides antialiasing, SMAA Low/Medium/High/Ultra, and spatial sample counts 1/2/4/8/16/32. Each override defaults null and preserves the scene setting. Applying preview or export quality copies the scene options; it never changes the source scene or another view. The neutral module retains no dependency on this optional backend assembly.

`ViewUpscalingOptions` explicitly requests Off or the implemented FSR1 spatial fallback, including its four presets and optional RCAS sharpness in stops [0,2]. The adapter maps these neutral settings to backend-owned types; the requested width/height remain final output dimensions while the backend computes the reduced input dimensions. GI still defaults Off. FSR1 is separate from the latest FSR SDK and DLSS integration requirements and does not claim temporal reconstruction.

The [stage tool](../../tools/Mmd.Modern.ViewOutput.Stage/README.md) verifies actual GPU capture, direct presentation, resize and explicit readback counts, PNG and four codec outputs. It additionally accepts a read-only PMX sample. Formal GUI and broader rendering compatibility remain outside this adapter milestone.

`ViewQualityOptions.TemporalUpscaling` separately selects real temporal FSR with NativeAA/Quality/Balanced/Performance/UltraPerformance presets. Supply the explicitly installed absolute FSR loader path to either adapter constructor, or configure the backend's `MMD_FSR_LOADER_PATH`. The neutral view contract contains no SDK paths or GPU handles. Unsupported camera/output or stacked SMAA/spatial supersampling/FSR1 combinations fail rather than silently switching providers. Supported GI combinations and SubTexture coverage are retained; inherited conflicts are rejected before recording GPU work.

Every capture renderer and realtime presenter owns independent native history. Export requests derive first-frame timing from their rational output FPS; subsequent captures use presentation timestamps and reset on repeated/skipped indices, time reversal or a source-time discontinuity. Their clock advances only after capture submits successfully. The capture overload accepting `ViewTemporalFrameState` lets hosts mark camera cuts, seeks/restarts and explicit reset. `PreviewSession` supplies wall-clock frame timing and `InvalidateTemporalHistoryAsync` records host seek/camera-cut changes without resetting ordinary orbit movement. `PreviewFrame.TemporalState` provides the same markers to direct hosts. Resize and GPU abort/reset handling remain owned by the D3D12 renderer.


XeSS is separately selectable with the seven official quality levels and a distinct optional `xessLibraryPath` (or `MMD_XESS_RUNTIME_PATH`); the FSR loader path is never routed to Intel. Input dimensions are obtained from the initialized SDK. All native XeSS API calls share one dedicated SDK thread, while every view retains its own history and GPU queue/fence lifecycle. Explicit temporal selection now defaults to NativeAA for detail preservation; Mode still defaults Off. The installed bundle3.0.2 reports SR runtime2.0.2 on the verified RTX2080. Actual unsupported device/runtime failures remain errors, with no silent provider fallback.

`ViewTemporalUpscalingMode.Dlss` selects the existing NGX SR implementation in both capture and realtime adapters. `DlssQuality` defaults to `NativeAa`; each requested quality and input resolution is verified by NGX on the actual device. Supply separate absolute `dlssBridgePath` (`mmd_dlss.dll`) and `dlssSdkDirectory` (containing the official `nvngx_dlss.dll`) constructor arguments, or configure `MMD_DLSS_BRIDGE_PATH` and `MMD_DLSS_SDK_DIRECTORY`. Components are external and load only when DLSS is selected. The neutral view options carry no SDK paths. Backend frame statistics expose `DlssDeviceQuery`, queried dimensions and submitted history; `D3D12FrameSession.QueryDlssCapabilities` performs a separate native initialization probe, which can submit GPU initialization but does not evaluate an application frame. SDK failures remain explicit errors. The product path currently requires a perspective camera and opaque composited output; SubTexture temporal coverage is supported, while stacked SMAA/SSAA/FSR1 remain rejected. Seeks/cuts reset history, and abort after evaluation recreates the NGX feature. This path does not provide frame generation.
