# MikuDance Advance

MikuDance Advance（简称 MDA）是一款运行在 Windows x64 桌面环境下的 MMD 工程编辑与渲染软件。

它围绕常见的 MMD 素材与工作流构建，将底层的模型动作、骨骼、IK、刚体与柔体物理以及工程编辑整合在一起，并在渲染层提供现代引擎与传统引擎两种选择。你可以在启动软件时根据当前工程的需要选定引擎，在统一的桌面界面里完成模型与动作导入、时间轴编辑、实时预览以及图像或视频导出。

## 核心功能说明

MDA 的日常功能主要涵盖素材读取、动画与物理处理、画面调整、工程管理以及渲染导出五个部分。

### 1. 素材与工程导入
- **模型、动作与姿态**：支持导入 `PMX`、`PMD` 模型文件，以及 `VMD` 动作数据和 `VPD` 姿态文件。
- **PMM 工程（有范围支持）**：支持读取旧有的 `PMM` 工程文件。需要注意的是，MDA 对 `PMM` 格式的支持有一定范围，**不能保证原工程中的全部特性无损还原**。导入后建议先检查镜头、骨骼动作、物理状态与画面表现是否符合预期。

### 2. 动作、物理与时间轴编辑
底层核心负责处理模型的动作解算、骨骼变换、IK（反向动力学）、刚体与柔体物理，以及外亲关系与工程编辑。
- **关键帧操作**：在选中目标模型后，可以在时间轴上**按范围选择**骨骼、表情与 IK 关键帧，并执行复制、粘贴、移动和删除操作。
- **撤销与重做**：编辑过程支持撤销与重做，便于在调整动作和表情时随时回退修改。

### 3. 画风、描边与预览控制
- **画风与材质描边**：支持现代画风呈现，并允许**逐材质调整描边倍率**，可以针对不同部位的材质分别微调轮廓线粗细。
- **预览与输出画质分离**：视口预览画质与最终导出画质单独设置。在编辑动画时可以按需调低预览画质，导出时再独立配置输出参数。
- **帧率显示与低帧率提醒**：软件状态栏会根据视口**实际呈现**的画面统计并显示当前 FPS。当帧率**持续 5 秒低于 24 FPS** 时，软件会发出提醒，但**不会自动修改你的预览画质**，是否调整设置完全由用户自己决定。

### 4. 工程保存与自动恢复
- **引擎专属格式与校验**：软件根据当前所选引擎分别使用 `.pma`（现代工程）与 `.pmc`（传统工程）两种格式，打开工程时会检查文件后缀和包内身份，防止跨引擎混用工程文件。
- **自动恢复副本**：软件维护了独立于手动保存的自动恢复副本，不会直接覆盖你平时手动保存的工程文件。

### 5. 图像与视频输出
- **同一引擎渲染**：预览与导出始终使用启动时选定的同一引擎完成。由于预览画质与输出画质各自独立配置，最终导出的画面效果会取决于你在导出面板里设定的参数。
- **导出格式与透明支持**：支持导出 `PNG` 单张图像、`PNG` 图像序列以及视频文件，并支持透明背景的 PNG 图像输出。
- **音频输入说明**：导出视频时，可使用**一条已启用的 PCM WAV 输入音轨**。这仅表示输入的音源文件需要是启用的 PCM WAV 格式，并不代表导出视频内部的音频编码为 PCM。

## 现代引擎与传统引擎对比

MDA 在每次启动时需要选择本次会话使用的渲染引擎。现代引擎与传统引擎面向不同的制作需求，各自的适用范围与限制如下：

| 对比项目 | 现代引擎 | 传统引擎 |
|---|---|---|
| **安装方式** | **默认安装** | **可选安装** |
| **图形接口** | Direct3D 12 (D3D12) | 面向传统 MMD/MME 兼容的渲染实现 |
| **工程文件格式** | 现代工程 `.pma`（校验文件后缀与内部身份） | 传统工程 `.pmc`（校验文件后缀与内部身份） |
| **特效与兼容性** | **不执行** `MME`、`FX`、`EMM` | **有范围支持** `MMD` / `MME`，**不保证支持所有特效，也不保证与原版逐像素一致** |
| **硬件光线追踪** | 需要硬件支持 DXR 1.1、Shader Model 6.5 及对应驱动，是否可用由程序检测 | 不适用 |
| **预览与导出** | 会话内预览与导出均使用现代引擎 | 会话内预览与导出均使用传统引擎 |

在开始制作前，可以根据工程是否需要传统 `MME` 特效来做决定：如果不需要旧版特效，直接使用默认的现代引擎并保存为 `.pma` 工程即可；如果工程需要用到传统特效，则在安装时勾选传统引擎，并在启动时选择传统引擎处理 `.pmc` 工程。

## 日常使用流程

从打开软件到完成一段动画的导出，日常工作流通常包含以下六个步骤。如果你刚接触这款软件，也可以阅读文字版的 [第一个动画教程](docs/guide/first-animation.md) 了解具体操作步骤。

1. **启动并选择引擎**
   启动 MDA，根据当前作品的需求选择进入现代引擎或传统引擎。进入工作区后，本次预览和后续导出都会使用所选的引擎。
2. **导入模型并选择用途**
   导入准备好的 `PMX` 或 `PMD` 模型文件，并在导入过程中按界面提示选择该模型的用途。
3. **选中模型后导入动作**
   在场景或列表中**先选中目标模型**，再导入 `VMD` 动作或 `VPD` 姿态数据。此时也可以根据需要调整各材质的描边倍率。
4. **时间轴预览与编辑**
   播放时间轴查看动作、表情、IK 与刚柔体物理的表现。需要修改时，选中模型并在时间轴上按范围选择对应的骨骼、表情或 IK 关键帧，通过复制、粘贴、移动、删除以及撤销重做来修正细节。如果状态栏持续 5 秒低于 24 FPS 并给出提醒，可以尝试降低预览画质以减轻实时渲染负担。
5. **保存对应格式的工程**
   将当前进度保存为与当前引擎对应的工程文件（现代引擎保存为 `.pma`，传统引擎保存为 `.pmc`）。软件的自动恢复副本与手动保存相互独立，日常编辑时仍建议养成定期手动保存的习惯。
6. **设置导出并先测试一小段**
   准备输出成片时，单独设置导出画质，并选择导出为 `PNG` 单图、`PNG` 序列或视频；视频可使用一条已启用的 PCM WAV 输入音轨。在开始长时间的完整渲染之前，**建议先在时间轴上选取一小段进行测试导出**，确认画面、动作和声音符合预期后，再正式导出完整片段。

## 硬件配置与运行环境建议

**目前 MDA 尚未完成最低配置测试。** 下表整理了面向日常使用与复杂工程的硬件配置建议，供配置环境时参考：

| 项目 | 日常建议配置 | 大工程与高负载建议 | 说明与注意事项 |
|---|---|---|---|
| **操作系统** | **Windows 11 x64**（建议） | **Windows 11 x64** | 安装器支持 Windows 10 x64；有关 Windows 10 的支持周期可参考微软官方页面 [Windows 10 支持状态](https://www.microsoft.com/en-us/windows/end-of-support)。 |
| **处理器 (CPU)** | **8 核 16 线程** | 高单核性能的 8 核 16 线程及以上处理器 | **单核性能十分重要**；软件内部分独立计算最多可使用 **16 路**。 |
| **内存 (RAM)** | **32 GB** | **64 GB**（大工程建议） | 复杂工程、多模型与高分辨率贴图会显著增加内存占用。 |
| **显卡 (GPU)** | 支持 **D3D12** 的独立显卡，**8 GB** 显存 | **12 GB – 16 GB** 显存（大场景或 4K 分辨率考虑） | **显存容量不代表渲染速度**，且更大的显存容量也不能保证在所有极端场景下都不会显存不足。 |
| **硬件光线追踪** | 按需使用 | 支持 DXR 1.1 与 Shader Model 6.5 的显卡 | 硬件光追需要 **DXR 1.1**、**Shader Model 6.5** 以及对应显卡驱动支持，当前环境是否可用**由程序在运行时检测**。 |
| **存储空间** | **SSD**，至少 **20 GB** 可用空间 | 高速 SSD，并根据输出规格预留额外空间 | 至少 20 GB 用于存放个人文件、自动恢复副本及日常输出；若需导出**长视频或大量图像序列，所需空间需另外计算**。 |

### 关于性能表现的说明
三维场景的渲染与物理计算开销受模型面数、刚柔体数量、贴图规格以及分辨率等因素的共同影响，**任何硬件配置都无法保证在所有工程下都能保持流畅**。

以开发过程中的一台**实际验证机**为例：
- **配置**：Intel Core i7-10875H（8 核 16 线程）、32 GB 内存、NVIDIA GeForce RTX 2080 SUPER Max-Q（8 GB 显存）
- **实测情况**：在这台设备上运行复杂工程时，视口预览帧率**仍会低于 30 FPS**。

遇到复杂工程帧率下降时，可以先尝试调低预览画质；导出画质仍可单独设置。实际效果取决于工程与硬件，正式导出前建议先测试一小段。

## 插件扩展与安全说明

MDA 支持通过插件扩展软件命令，插件的安装与运行方式如下：

- **导入与手动启用**：打包好的插件为 `.zip` 格式。你可以在顶部菜单栏依次打开 **“帮助 → 插件”** 导入插件 ZIP 包，并在导入后**手动启用**该插件。
- **接口范围（API 1）**：当前插件接口版本为 `API 1`，目前提供**命令扩展**功能。
- **运行与安全**：插件在启用后会**与 MDA 宿主程序在同一个进程内运行，没有安全沙箱隔离**。请仅导入和启用你明确了解且信任来源的插件。

有关插件结构与接口调用的具体说明，请参考 [插件开发文档](docs/development/plugins.md)。

## 软件模块组成

MDA 按职责划分为六个产品模块：

1. **MMD 核心**：负责 `PMX`、`PMD`、`VMD`、`VPD` 及有范围的 `PMM` 数据解析，处理模型动作、骨骼、IK、刚体与柔体物理、外亲关系以及工程编辑逻辑。
2. **现代引擎**：基于 D3D12 的渲染后端，对应 `.pma` 现代工程，负责现代画风、逐材质描边倍率调整以及经程序检测可用时的硬件光线追踪渲染。
3. **传统引擎**：可选安装的传统渲染后端，对应 `.pmc` 传统工程，有范围支持 `MMD` / `MME`（不保证所有特效兼容或与原版逐像素一致）。
4. **GUI（图形用户界面）**：负责主界面、菜单、参数面板、时间轴关键帧的范围选择与编辑交互、状态栏实际呈现 FPS 显示与持续 5 秒低于 24 FPS 的提醒等界面逻辑。
5. **视图**：负责视口画面的实际呈现，以及预览与最终输出（PNG 单图、PNG 序列、视频）的编排调度，管理预览画质与输出画质的独立设置。
6. **插件加载器**：负责插件清单校验、加载与停用、依赖管理和 `API 1` 命令注册；“帮助 → 插件”由 GUI 调用这些能力。
